% ==================== RÉSUMÉ EXÉCUTIF ====================
\chapter*{Résumé Exécutif}
\addcontentsline{toc}{chapter}{Résumé Exécutif}

Ce rapport présente le développement complet d'un système robotique autonome conçu pour les applications de stérilisation. Le projet combine une infrastructure middleware Robot Operating System 2 (ROS2) sophistiquée avec une application mobile native développée en React Native, permettant le contrôle et le suivi des opérations de stérilisation autonomes.

Le système a été développé en deux composantes majeures : le système embarcation ROS2 responsable de la navigation autonome, de la cartographie et de l'exploration, et l'application mobile qui fournit une interface utilisateur intuitive pour la gestion des tâches de stérilisation et le suivi en temps réel du statut du robot.

Cette architecture permet une intégration transparente entre le matériel robotique et les interfaces de l'utilisateur, tout en maintenant des standards élevés de sécurité et de fiabilité. Le rapport couvre l'architecture globale, les composants techniques, les défis rencontrés et les solutions implémentées.

\chapter{Introduction}

\section{Contexte et Motivation}

La robotique autonome a connu des avancées spectaculaires ces dernières années, permettant l'automatisation de tâches complexes dans divers domaines. Les applications de stérilisation, en particulier, bénéficient grandement de l'automatisation et de la précision des systèmes robotiques. La capacité d'un robot à naviguer de manière autonome dans un environnement non structuré, tout en effectuant des tâches de stérilisation, représente une avancée significative dans les domaines médical et industriel.

Ce projet vise à développer un système robotique complet capable de :
\begin{itemize}
  \item Naviguer de manière autonome dans des environnements complexes
  \item Construire et maintenir des cartes de l'environnement
  \item Détecter et explorer les frontières non explorées
  \item Fournir une interface utilisateur pour la supervision et le contrôle
  \item Effectuer des opérations de stérilisation de manière sécurisée et efficace
\end{itemize}

\section{Objectifs du Projet}

Les objectifs principaux du projet sont :

\begin{enumerate}
  \item \textbf{Architecture Robuste} : Concevoir une architecture logicielle distribuée utilisant ROS2 capable de gérer les complexités de la navigation autonome et de la coordination des tâches.
  
  \item \textbf{Navigation Autonome} : Implémenter un système d'exploration autonome utilisant une détection des frontières basée sur la vision et une sélection intelligente des objectifs.
  
  \item \textbf{Interface Utilisateur Intuitive} : Développer une application mobile native offrant un contrôle facile et un suivi en temps réel des opérations du robot.
  
  \item \textbf{Sécurité et Fiabilité} : Mettre en place des mécanismes de sécurité robustes, y compris les arrêts d'urgence et la récupération automatique en cas de défaillance.
  
  \item \textbf{Performance et Optimisation} : Optimiser les paramètres de navigation et d'exploration pour assurer une couverture maximale avec une efficacité énergétique minimale.
\end{enumerate}

% ==================== TECHNOLOGIES ET FRAMEWORKS ====================
\chapter{Technologies et Frameworks}

\section{Robot Operating System 2 (ROS2)}

ROS2 est un middleware robotique de nouvelle génération qui fournit un cadre flexible pour construire des applications robotiques complexes. Contrairement à ROS1, ROS2 offre :

\begin{itemize}
  \item \textbf{Architecture distribuée} basée sur DDS (Data Distribution Service)
  \item \textbf{Temps réel} : Support des systèmes temps réel dur et mou
  \item \textbf{Sécurité} : Intégration de la sécurité au niveau du middleware
  \item \textbf{Scalabilité} : Architecture modulaire permettant le déploiement sur plusieurs machines
  \item \textbf{Langage agnostique} : Support de multiples langages (C++, Python, Java)
\end{itemize}

Dans ce projet, ROS2 est utilisé comme base pour tous les systèmes embarqués du robot, incluant la navigation, la localisation, la cartographie et l'exploration.

\section{Navigation2}

Navigation2 est un ensemble complet de tools et d'algorithmes pour la navigation autonome des robots mobiles. Il fournit :

\begin{itemize}
  \item \textbf{Planificateurs de trajets} : Calcul de chemins optimisés globalement et localement
  \item \textbf{Contrôleurs de mouvement} : Suivi précis des trajectoires planifiées
  \item \textbf{Arbres de comportement} : Orchestration des tâches de navigation
  \item \textbf{Gérance des cartes de coûts} : Représentation dynamique de l'espace navigable
  \item \textbf{Localisation} : Localisation par rapport à une carte connue ou construction de la carte
\end{itemize}

\section{SLAM (Simultaneous Localization and Mapping)}

Le SLAM est crucial pour permettre au robot de naviguer dans des environnements inconnus. Ce projet utilise SLAM Toolbox qui implémente des algorithmes graphiques robustes pour :

\begin{itemize}
  \item Construire une carte cohérente de l'environnement
  \item Localiser le robot dans cette carte
  \item Gérer les fermetures de boucles pour corriger la dérive odométrique
\end{itemize}

\section{React Native}

React Native est un framework de développement d'applications mobiles natives basé sur JavaScript et React. Il offre :

\begin{itemize}
  \item \textbf{Code partagé} : Un même codebase pour iOS et Android
  \item \textbf{Performance native} : Accès direct aux APIs natives du système d'exploitation
  \item \textbf{Écosystème riche} : Large bibliothèque de composants et de libraries
  \item \textbf{Développement rapide} : Hot reload et débogage intégré
\end{itemize}

\section{OpenCV}

OpenCV est utilisé pour le traitement d'images et l'analyse des cartes d'occupation. Elle fournit les algorithmes essentiels pour :

\begin{itemize}
  \item Détection des frontières dans les grilles d'occupation
  \item Clustering et groupement des cellules de frontière
  \item Calcul de gains informationnels
\end{itemize}

\section{Firebase}

Firebase est utilisé pour l'authentification et la synchronisation des données utilisateur dans l'application mobile. Il offre :

\begin{itemize}
  \item Authentification sécurisée avec gestion des sessions
  \item Base de données temps réel pour la synchronisation des données
  \item Stockage d'objets pour les historiques et les rapports
\end{itemize}

% ==================== SYSTÈME ROS2 - EXPLORATION (PARTIE 1) ====================
\chapter{Infrastructure ROS2 : Système de Navigation et Exploration}

\section{Présentation générale}

L'infrastructure ROS2 est le cœur du système robotique, responsable de tous les aspects de la navigation autonome, de la cartographie, et de l'exploration. Elle est composée de plusieurs modules spécialisés qui travaillent ensemble de manière coordonnée pour permettre au robot de naviguer efficacement.

\section{Module de Détection des Frontières}

\subsection{Concept et Importance}

La détection des frontières est un élément fondamental du système d'exploration autonome. Une frontière est définie comme la limite entre l'espace connu (libre ou occupé) et l'espace inconnu (non exploré). Le robot utilise ces frontières comme points d'intérêt pour diriger son exploration.

L'algorithme de détection des frontières :

\begin{enumerate}
  \item Reçoit la grille d'occupation publiée par le système SLAM
  \item Identifie toutes les cellules qui sont libres et adjacentes à des cellules inconnues
  \item Regroupe ces cellules en amas de frontières connexes
  \item Calcule le centroïde de chaque amas
  \item Filtre les frontières selon la taille minimale et la distance maximale
\end{enumerate}

\subsection{Algorithme détaillé}

\begin{algorithm}[H]
\caption{Détection des Frontières}
\begin{algorithmic}
  \State Convertir grille d'occupation en image OpenCV
  \State Initialiser liste des cellules de frontière
  
  \For{chaque cellule non-limite de la grille}
    \If{cellule est libre ET a un voisin inconnu}
      \State Ajouter à liste de cellules frontière
    \EndIf
  \EndFor
  
  \State frontières $\leftarrow$ grouper cellules frontière connexes
  
  \For{chaque frontière}
    \If{taille $\geq$ seuil ET distance $\leq$ max\_distance}
      \State Calculer gain informatif
      \State Vérifier accessibilité
      \If{accessible}
        \State Ajouter à frontières filtrées
      \EndIf
    \EndIf
  \EndFor
  
  \State \Return frontières filtrées
\end{algorithmic}
\end{algorithm}

\subsection{Implémentation C++}

L'implémentation utilise les bibliothèques ROS2 standards et OpenCV pour :

\begin{itemize}
  \item Abonnement à la topic \texttt{/map} pour recevoir les mises à jour de la grille d'occupation
  \item Traitement des images avec OpenCV pour identifier les frontières
  \item Publication des marqueurs de visualisation pour déboguer dans RViz
  \item Publication des frontières détectées sous forme de marqueurs
\end{itemize}

Les paramètres clés incluent :
\begin{itemize}
  \item \texttt{min\_frontier\_size} : Taille minimale d'une frontière en cellules
  \item \texttt{max\_frontier\_distance} : Distance maximale à partir du robot
  \item \texttt{information\_radius} : Rayon pour calculer le gain informatif
  \item \texttt{frontier\_travel\_point\_distance} : Distance minimum aux points de voyage
\end{itemize}

\section{Module de Coordination de l'Exploration}

\subsection{Architecture et États}

Le coordinateur d'exploration gère la machine d'états du robot lors de l'exploration. Les états principaux sont :

\begin{enumerate}
  \item \textbf{IDLE} : Robot inactif, en attente de commande
  \item \textbf{DETECTING\_ENVIRONMENT} : Phase initiale de détection du type d'environnement
  \item \textbf{EXPLORING} : Exploration active avec sélection et navigation vers les frontières
  \item \textbf{NAVIGATING\_TO\_FRONTIER} : Navigation en cours vers une frontière sélectionnée
  \item \textbf{STUCK\_RECOVERY} : Récupération quand le robot est bloqué
  \item \textbf{EXPLORATION\_COMPLETE} : Exploration terminée avec succès
  \item \textbf{ERROR} : État d'erreur nécessitant intervention
\end{enumerate}

\subsection{Sélection Intelligente des Frontières}

Le système implémente une sélection intelligente basée sur un score pondéré :

$$\text{Score} = \frac{\text{Information Gain}}{1.0 + \text{Distance} \times 0.1}$$

Cette formule équilibre deux objectifs :
\begin{itemize}
  \item Maximiser le gain informatif (explorant les zones avec plus d'informations)
  \item Minimiser la distance totale parcourue (efficacité énergétique)
\end{itemize}

\subsection{Gestion des Situations Bloquées}

Quand le robot détecte qu'il est bloqué (absence de mouvement significatif pendant une durée définie), il active une séquence de récupération multi-étapes :

\begin{enumerate}
  \item \textbf{Recul intelligent} : Marche arrière avec évitement d'obstacles
  \item \textbf{Rotation adaptative} : Rotation avec vitesse variable
  \item \textbf{Nettoyage des cartes de coûts} : Réinitialisation des couches de perception
  \item \textbf{Re-planification} : Calcul de nouveaux trajets
\end{enumerate}

\subsection{Monitoring et Optimisation Dynamique}

Le coordinateur implémente :

\begin{itemize}
  \item \textbf{Surveillance de performance} : Suivi des métriques d'efficacité
  \item \textbf{Adaptation dynamique} : Ajustement des tolérances basé sur la vitesse actuelle
  \item \textbf{Adaptation environnementale} : Ajustement des paramètres selon les caractéristiques observées
  \item \textbf{Mise à jour adaptative} : Ajustement continu des paramètres de navigation
\end{itemize}

\section{Module de Localisation et Cartographie (SLAM)}

\subsection{Configuration SLAM}

Le système SLAM utilise SLAM Toolbox, configuré pour :

\begin{itemize}
  \item Recevoir les données du capteur LIDAR
  \item Construire une carte de l'environnement
  \item Maintenir la pose du robot
  \item Gérer les fermetures de boucles automatiquement
\end{itemize}

\subsection{Grille d'Occupation}

La grille d'occupation publiée par le SLAM représente l'environnement comme une grille 2D où :
\begin{itemize}
  \item $0$ = espace libre (navigable)
  \item $100$ = espace occupé (obstacle)
  \item $-1$ = espace inconnu (non exploré)
\end{itemize}

Résolution typique : \texttt{0.05m par cellule}

\section{Module de Navigation (Navigation2)}

\subsection{Composants principaux}

Navigation2 fournit :

\begin{itemize}
  \item \textbf{Planner Global} : Calcul de trajets de haut niveau (Theta* ou RRT*)
  \item \textbf{Planner Local} : Suivi précis des trajets en évitant les obstacles dynamiques
  \item \textbf{Recovery Behaviors} : Stratégies de récupération en cas d'impasse
  \item \textbf{Cost Map Manager} : Gestion des cartes de coûts statiques et dynamiques
\end{itemize}

\subsection{Paramètres de Navigation}

Les paramètres clés de Navigation2 incluent :

\begin{table}[H]

\hline

\hline

\end{table}

% ==================== DÉFIS ET SOLUTIONS ====================
\chapter{Défis Techniques et Solutions Implémentées}

\section{Défis dans le Système ROS2}

\subsection{Exploration Efficace}

\textbf{Défi} : Assurer que le robot explore de manière efficace sans visiter les mêmes frontières à répétition ou entrer dans des boucles infinies.

\textbf{Solution} : 
\begin{itemize}
  \item Implémentation d'une liste des frontières récemment visitées
  \item Ajustement dynamique des tolérances d'atteinte d'objectif
  \item Sélection intelligente basée sur le score pondéré des gains informatifs et des distances
\end{itemize}

\subsection{Récupération du Blocage}

\textbf{Défi} : Détecter quand le robot est coincé et le libérer de manière robuste.

\textbf{Solution} :
\begin{itemize}
  \item Détection du blocage basée sur l'absence de mouvement détectable
  \item Stratégies de récupération multi-étapes avec rotation et marche arrière
  \item Nettoyage des cartes de coûts et re-planification
  \item Augmentation progressive de l'agressivité des stratégies si la récupération échoue
\end{itemize}

\subsection{Paramètres de Navigation Adaptatifs}

\textbf{Défi} : Trouver les bons paramètres de navigation qui fonctionnent dans différents environnements.

\textbf{Solution} :
\begin{itemize}
  \item Implémentation de tolérance dynamique basée sur la vitesse actuelle
  \item Adaptation des paramètres selon les caractéristiques de l'environnement
  \item Surveillance continue des performances et ajustement automatique
\end{itemize}

\section{Défis dans l'Application Mobile}

\subsection{Synchronisation Temps Réel}

\textbf{Défi} : Maintenir une synchronisation temps réel avec le robot tout en gérant la latence réseau et les connexions instables.

\textbf{Solution} :
\begin{itemize}
  \item Utilisation de Zustand pour la gestion d'état locale
  \item Mise en cache des données pour affichage offline
  \item Retry automatique avec backoff exponentiel pour les requêtes échouées
  \item Vérification périodique de la connexion avec reconnexion automatique
\end{itemize}

\subsection{Performance et Consommation de Batterie}

\textbf{Défi} : Maintenir une application réactive tout en minimisant la consommation de batterie.

\textbf{Solution} :
\begin{itemize}
  \item Optimisation des requêtes API (pagination, compression)
  \item Utilisation de SWR pour le caching efficace des données
  \item Réduction de la fréquence de polling selon l'état de l'application
  \item Optimisation des rendus React avec memoization
\end{itemize}

\subsection{Affichage de Cartes en Temps Réel}

\textbf{Défi} : Afficher les mises à jour de cartes (grille d'occupation) en temps réel sans ralentir l'application.

\textbf{Solution} :
\begin{itemize}
  \item Compression des données de carte avant transmission
  \item Mise à jour incrémentale des régions modifiées
  \item Rendu optimisé avec Canvas au lieu de composants React
  \item Limitation de la fréquence de mise à jour visuelle
\end{itemize}

\section{Défis d'Intégration

\subsection{Latence Réseau}

\textbf{Défi} : Gérer les délais de communication entre l'application mobile et le robot.

\textbf{Solution} :
\begin{itemize}
  \item Ajustement des timeouts selon les conditions réseau
  \item Feedback utilisateur immédiat avec mise à jour différée
  \item Rollback des commandes non confirmées par le robot
\end{itemize}

\subsection{Fiabilité et Disponibilité}

\textbf{Défi} : Assurer un fonctionnement fiable avec graceful degradation.

\textbf{Solution} :
\begin{itemize}
  \item Watchdog timers pour détecter les défaillances
  \item Heartbeat messages réguliers
  \item Mode offline avec queue de commandes
  \item Logging détaillé pour diagnostic
\end{itemize}
